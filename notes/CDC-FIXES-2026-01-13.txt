PROBLEM SUMMARY
================================================================================

ops-log-08 showed CDC charge operation failing with 0.000A peak current after
user cancelled at 1 minute.

Analysis revealed CDC experiment had TWO separate configuration problems,
both causing CV mode to fail:

ISSUE 1: LOW POWER LIMIT (20W)
  - CDC_POWER_LIMIT_W = 20W
  - PSB interprets "voltage setpoint + low power limit" as CP mode
  - Same issue as Phase 3 baseline (was using 30W)

ISSUE 2: WRITING SETPOINT REGISTERS
  - CDC was writing REG 501 (SET_CURRENT) = 3.3A
  - CDC was writing REG 499 (SINK_MODE_CURRENT) = 5.0A
  - Multiple non-zero setpoints cause mode selection issues
  - Same issue as initial Phase 3 baseline problem

Both issues needed to be fixed for CDC to work correctly!

================================================================================
ISSUE 1: LOW POWER LIMIT (20W → 1224W)
================================================================================

DISCOVERY:
ops-log-08 showed power limit being set to 1224W (line 260) which suggested
the fix was applied, but the CDC .h file still had:
  #define CDC_POWER_LIMIT_W  20.0  // "20W limit prevents CP mode"

The comment was backwards - low power limits CAUSE CP mode!

ROOT CAUSE:
From Phase 3 debugging (ops-log-07), we learned:
  - PSB firmware examines BOTH setpoint AND limit registers
  - Voltage setpoint + LOW power limit → CP mode
  - Voltage setpoint + HIGH power limit → CV mode

CDC was using 20W which is even lower than Phase 3's 30W!

FIX (commit b6d3657):
Changed CDC_POWER_LIMIT_W from 20W to PSB_SAFE_POWER_MAX (1224W):

  exp_cdc.h:
    Before: #define CDC_POWER_LIMIT_W  20.0
    After:  #define CDC_POWER_LIMIT_W  PSB_SAFE_POWER_MAX  // 1224W

This matches:
  - Phase 3 baseline charging (now uses 1224W)
  - Battery_GoToVoltage() (uses 1224W)
  - PSB initialization (sets limits to 1224W)

================================================================================
ISSUE 2: WRITING SETPOINT REGISTERS (ops-log-08 revealed)
================================================================================

DISCOVERY:
ops-log-08 lines 252-258 showed:
  [PSB] *** WRITING REG 501 (SET_CURRENT): 3.30A (0x0B43) - WILL ENTER CC MODE ***
  [PSB] *** WRITING REG 499 (SINK_MODE_CURRENT): 5.00A (0x1110) - MAY ENTER SINK CC MODE ***

CDC was writing to SETPOINT registers even though comments said "Set limits"!

COMPARISON WITH WORKING CODE:

Battery_GoToVoltage() (WORKS):
  - Does NOT write REG 501 (SET_CURRENT)
  - Does NOT write REG 499 (SINK_MODE_CURRENT)
  - ONLY writes REG 500 (SET_VOLTAGE)
  - Leaves sink decoys (10A/100W) from initialization
  - Uses high limit registers (9002/9008/9004/9005)

CDC Before Fix (FAILED):
  - Wrote REG 501 = 3.3A via PSB_SetCurrentQueued() ❌
  - Wrote REG 499 = 5.0A via PSB_SetSinkCurrentQueued() ❌
  - Multiple non-zero setpoints → mode ambiguity

ROOT CAUSE:
The code comments said "Set current limits" but the functions used were:
  - PSB_SetCurrentQueued() → writes REG 501 SETPOINT
  - PSB_SetSinkCurrentQueued() → writes REG 499 SETPOINT

Should have used:
  - PSB_SetCurrentLimitsQueued() → writes REG 9002 LIMIT
  - PSB_SetSinkCurrentLimitsQueued() → writes REG 9008 LIMIT

FIX (commit fffa9cd):
Changed CDC to use LIMIT register functions:

  exp_cdc.c Before:
    PSB_SetCurrentQueued(chargeCurrent, ...);           // REG 501 ❌
    PSB_SetSinkCurrentQueued(dischargeCurrent, ...);    // REG 499 ❌

  exp_cdc.c After:
    PSB_SetCurrentLimitsQueued(0.0, chargeCurrent, ...);      // REG 9002 ✓
    PSB_SetSinkCurrentLimitsQueued(0.0, dischargeCurrent, ...); // REG 9008 ✓

This ensures:
  1. REG 501 (SET_CURRENT) remains 0.0A
  2. REG 499 (SINK_MODE_CURRENT) keeps init decoy (10A)
  3. Only REG 500 (SET_VOLTAGE) is the active setpoint
  4. Current is constrained by LIMIT registers (9002/9008)

================================================================================
LESSONS LEARNED
================================================================================

1. FUNCTION NAMES CAN BE MISLEADING:
   - PSB_SetCurrentQueued() sounds like "set limit" but writes SETPOINT
   - PSB_SetCurrentLimitsQueued() actually writes LIMIT register
   - Always verify which register a function writes to

2. TWO INDEPENDENT FAILURE MODES:
   - Low power limits cause CP mode (limit register issue)
   - Multiple setpoints cause mode ambiguity (setpoint register issue)
   - Both must be fixed for CV mode to work

3. WORKING CODE IS THE BEST REFERENCE:
   - Battery_GoToVoltage() had the correct pattern all along
   - When debugging, always compare with working implementations
   - Match the successful pattern exactly

4. LOGS ARE ESSENTIAL FOR DIAGNOSIS:
   - ops-log-08 clearly showed "WRITING REG 501: 3.30A"
   - Without detailed register write logging, would have been much harder
   - Register dumps before/after operations are invaluable

5. COMMENTS CAN BE WRONG:
   - CDC comment said "20W limit prevents CP mode"
   - Reality: low limits CAUSE CP mode
   - Always verify assumptions against behavior

ISSUE 3: LIMIT/SETPOINT REGISTER CONFLICT (ops-log-09 revealed)
================================================================================

DISCOVERY:
ops-log-09 showed a new failure mode at lines 255-257:
  2026-01-13 17:13:17 [INFO] [PSB] Setting sink max current: 5.00A
  2026-01-13 17:13:17 [ERROR] [PSB] Modbus exception code: 0x03 - Illegal data value
  2026-01-13 17:13:17 [ERROR] Failed to set sink current limit: Invalid response

PSB rejected the sink current limit write!

ROOT CAUSE:
PSB firmware enforces: LIMIT registers must be >= SETPOINT registers

From initialization:
  - REG 499 (SINK_MODE_CURRENT) = 10A (decoy SETPOINT)
  - REG 9008 (SINK_CURRENT_MAX) = 61.2A (high LIMIT)

CDC was trying to set:
  - REG 9008 (SINK_CURRENT_MAX) = 5A (discharge limit)

PSB firmware validation:
  - LIMIT (5A) < SETPOINT (10A) → "Illegal data value" error ❌

THE CONFLICT:
  Decoy setpoints (10A/100W) are necessary for mode selection, but they
  create a minimum threshold for limit registers. Setting limit < decoy
  causes PSB to reject the write.

WHY SETTING LIMITS SEEMED NECESSARY:
  User wants to constrain current to safe levels (e.g., 3.3A charge, 5A discharge)
  Natural approach: set current limit registers to these values
  BUT: conflicts with decoy setpoint values!

BATTERY_GOTOVOLTAGE() PATTERN (already correct):
battery_utils.c lines 127-142 explain the solution:

  "NOTE: We do NOT modify limit registers here!

  Discovery from ops-log-2026-01-12-10.txt:
  - During init, sink current SETPOINT = 10A (mode selection decoy)
  - Trying to set sink current LIMIT < SETPOINT causes 'Illegal data value' error
  - The PSB rejects setting limits lower than setpoints

  Solution: Leave limits at their high initialization values (61.2A, 1224W).
  The setpoints (10A, 100W) are 'decoys' to prevent CC/CP mode selection.
  In CV mode, the actual current is naturally limited by:
    1. Voltage difference (battery V vs target V)
    2. Battery internal resistance
    3. PSB's natural current capability
  The decoy setpoints and high limits work together to ensure CV mode without conflicts."

NATURAL CURRENT LIMITING IN CV MODE:

When PSB operates in CV mode, current is automatically controlled by physics:

  Ohm's Law: I = (V_target - V_battery) / R_total

  Where R_total = R_battery + R_wiring + R_PSB_internal

  Example (charging):
    - Battery: 2.7V
    - Target: 4.2V
    - Voltage difference: 1.5V
    - Battery resistance: ~50mΩ at high SOC
    - Current: 1.5V / 0.05Ω = 30A max

  But as battery charges:
    - Battery voltage increases toward 4.2V
    - Voltage difference decreases
    - Current naturally decreases (I = ΔV / R)
    - At 4.15V: ΔV = 0.05V → I ≈ 1A
    - At 4.19V: ΔV = 0.01V → I ≈ 200mA
    - At 4.20V: ΔV = 0V → I = 0A (done)

So in CV mode:
  - PSB maintains target voltage (4.2V)
  - Current flows based on voltage difference
  - High limit (61.2A) doesn't matter - physics limits current
  - Decoy setpoints (10A/100W) guide mode selection
  - No need to set explicit current limits!

FIX (commit 3e69e95):
Removed ALL limit register writes from CDC, matching Battery_GoToVoltage():

  exp_cdc.c Before (FAILED):
    PSB_SetCurrentLimitsQueued(0.0, chargeCurrent, ...)     → REG 9002 = 3.3A
    PSB_SetSinkCurrentLimitsQueued(0.0, dischargeCurrent, ...) → REG 9008 = 5A ❌ conflict!
    PSB_SetPowerLimitQueued(1224W, ...)                     → REG 9004 = 1224W
    PSB_SetSinkPowerLimitQueued(1224W, ...)                 → REG 9005 = 1224W

  exp_cdc.c After (CORRECT):
    // Don't modify ANY limit registers!
    // Use initialization values:
    //   REG 9002 = 61.2A (source current)
    //   REG 9004 = 1224W (source power)
    //   REG 9008 = 61.2A (sink current)
    //   REG 9005 = 1224W (sink power)
    // Current naturally limited by voltage difference in CV mode

WHY THIS WORKS:
  1. No limit/setpoint conflicts - limits stay at safe high values
  2. Decoy setpoints (10A/100W) ensure CV mode selection
  3. High limits (61.2A/1224W) don't restrict CV operation
  4. Physics (Ohm's law) naturally limits current based on voltage
  5. Battery internal resistance provides current limiting
  6. As battery charges/discharges, current adjusts automatically

SAFETY CONSIDERATIONS:
  Q: Won't 61.2A limit be dangerous?
  A: No, because:
     - In CV mode, voltage difference determines current (Ohm's law)
     - Battery internal resistance limits current (typically 50-200mΩ)
     - PSB hardware current limit (51A actual max)
     - Voltage difference is small during normal operation
     - Example: 1V difference with 100mΩ resistance = 10A max

  Q: What if battery is short-circuited?
  A: Multiple protections:
     - PSB hardware current limit (51A)
     - Battery internal fuse/protection
     - Voltage difference in CV mode limits current
     - Not relying on software limits for safety

TESTING PROCEDURE
================================================================================

1. Build project in LabWindows/CVI 2020
2. Connect to PSB 10000 on COM3
3. Run CDC charge operation (target 4.2V)
4. Monitor logs for:

   CONFIGURATION:
     - "Using initialization limits (61.2A/1224W) - not modifying limit registers"
     - "Source current limit: 61.2A (REG 9002 from init, not changed)"
     - "Sink current limit: 61.2A (REG 9008 from init, not changed)"
     - "Source power limit: 1224W (REG 9004 from init, HIGH to prevent CP mode)"
     - "Sink power limit: 1224W (REG 9005 from init, HIGH to prevent CP mode)"

   NO SETPOINT WRITES:
     - Should NOT see "*** WRITING REG 501 (SET_CURRENT)" ← BAD!
     - Should NOT see "*** WRITING REG 499 (SINK_MODE_CURRENT)" ← BAD!

   NO LIMIT WRITES (after init):
     - Should NOT see "Setting max current: 3.30A" ← Would conflict!
     - Should NOT see "Setting sink max current: 5.00A" ← Would cause "Illegal data value"!

   AFTER OUTPUT ENABLE:
     - Current should be NON-ZERO (e.g., 0.5A - 3.3A depending on battery)
     - Battery should charge toward 4.2V
     - Mode should remain CV throughout

5. If successful:
   - Battery charges normally to 4.2V
   - Current decreases as voltage approaches target
   - Operation completes successfully

6. Test discharge similarly:
   - Set target below current voltage (e.g., 2.7V)
   - Should see discharge current flowing
   - CV SINK mode should be maintained
