================================================================================
ROOT CAUSE DISCOVERED
================================================================================

The critical clue was in ops-log-07, lines 437-439:

  DIAGNOSTIC: [2/4] Setting power LIMIT to 0.0 W (REG 9004)
  [PSB] Setting max power: 30.00W
  DIAGNOSTIC: Power limit command completed

The diagnostic message SAID "0.0 W" but PSB actually wrote "30.00W"!

Looking at exp_baseline.c line 1455:
  LogMessage("DIAGNOSTIC: [2/4] Setting power LIMIT to %.1f W (REG 9004)",
             BASELINE_POWER_LIMIT);
  result = PSB_SetPowerLimitQueued(BASELINE_POWER_LIMIT, DEVICE_PRIORITY_NORMAL);

And exp_baseline.h line 66:
  #define BASELINE_POWER_LIMIT            30      // 30W power limit

**Phase 3 charging was setting REG 9004 (POWER_MAX) to 30W!**

Comparing with successful discharge operations in battery_utils.c line 142:
  LogMessage("Using initialization setpoints (10A/100W decoys) and
             high limits (61.2A/1224W)");

**Battery_GoToVoltage() uses 1224W power limit, NOT 30W!**

PSB MODE SELECTION LOGIC (COMPLETE PICTURE):

When output is enabled, PSB firmware examines BOTH setpoint registers (498-502)
AND limit registers (9000-9009):

  If voltage setpoint is non-zero AND power limit is LOW (e.g., 30W):
    → Interprets as "constant voltage with power constraint"
    → Selects CP (Constant Power) mode to honor the power limit
    → Power limit = REG 9004 value (30W)
    → Result: CP mode, current limited by P/V = 30W/4.2V = 7.1A max

  If voltage setpoint is non-zero AND power limit is HIGH (e.g., 1224W):
    → Interprets as "pure constant voltage with non-restrictive limit"
    → Selects CV (Constant Voltage) mode
    → Current controlled naturally by voltage difference
    → Result: CV mode, power limit doesn't restrict operation

CRITICAL INSIGHT:
  Limit registers (particularly REG 9004 POWER_MAX) DO affect mode selection!
  They're not just passive safety limits - the PSB firmware uses them as part
  of its mode selection algorithm. A LOW power limit triggers CP mode, while
  a HIGH power limit allows CV mode.

================================================================================
SOLUTION: USE HIGH POWER LIMIT LIKE DISCHARGE OPERATIONS
================================================================================

The fix is simple - match the successful discharge pattern:

BEFORE (FAILED):
  #define BASELINE_POWER_LIMIT            30      // 30W power limit

  result = PSB_SetPowerLimitQueued(BASELINE_POWER_LIMIT, DEVICE_PRIORITY_NORMAL);

  Result:
    REG 9004 = 30W → PSB enters CP mode

AFTER (CORRECT):
  // Use high power limit to avoid triggering CP mode
  result = PSB_SetPowerLimitQueued(PSB_SAFE_POWER_MAX, DEVICE_PRIORITY_NORMAL);

  Result:
    REG 9004 = 1224W → PSB stays in CV mode

psb10000_dll.h defines:
  #define PSB_SAFE_POWER_MAX      1224.0  // W (102% of nominal)

This matches the power limit used by:
  1. PSB initialization (psb10000_queue.c line 748)
  2. Battery_GoToVoltage() (battery_utils.c line 142)
  3. PSB safe limits setup (psb10000_queue.c)

================================================================================

1. LIMIT REGISTERS CAN AFFECT MODE SELECTION:
   - Not just passive safety constraints
   - PSB firmware uses them in mode selection algorithm
   - Low limits can trigger mode changes (CV → CP)

2. LOOK AT WORKING CODE FIRST:
   - Battery_GoToVoltage() had the answer all along (1224W power limit)
   - Should have compared ALL registers (setpoints AND limits) earlier
   - Working reference implementations are invaluable

3. CROSS-REFERENCE REGISTER DUMPS WITH CODE:
   - ops-log-07 showed "30W" in register dump
   - Code showed BASELINE_POWER_LIMIT = 30
   - Should have connected these dots sooner

4. BEWARE OF MISLEADING LOG MESSAGES:
   - Log said "Setting power LIMIT to 0.0 W"
   - But code actually used BASELINE_POWER_LIMIT (30W)
   - Always verify log messages match actual values

5. MODE SELECTION IS COMPLEX:
   - Not just "last register written wins"
   - Not just setpoint registers (498-502)
   - Firmware evaluates BOTH setpoints AND limits
   - Low power limit + voltage setpoint = CP mode
   - High power limit + voltage setpoint = CV mode

6. DEBUGGING REQUIRES COMPLETE PICTURE:
   - Must examine ALL configuration: setpoints, limits, timing
   - A single "wrong" value in a limit register can break everything
   - Register dumps are essential but must be analyzed holistically

================================================================================
PSB FIRMWARE MODE SELECTION ALGORITHM (REVISED COMPLETE UNDERSTANDING)
================================================================================

Based on 40+ commits and comprehensive testing, the PSB firmware mode selection
logic appears to be:

STEP 1: Check which SETPOINT registers (498-502) have non-zero values
  - If only REG 500 (voltage): Candidate for CV mode
  - If REG 501 (current) non-zero: Candidate for CC mode
  - If REG 502 (power) non-zero: Candidate for CP mode
  - If multiple setpoints: Ambiguous, firmware chooses based on additional logic

STEP 2: Check LIMIT registers (9000-9009) for restrictive values
  - If REG 9004 (POWER_MAX) is LOW relative to expected operation:
    → Firmware interprets as "power-constrained operation"
    → OVERRIDES CV candidate and selects CP mode
    → Example: CV with 30W power limit → CP mode
  - If REG 9004 (POWER_MAX) is HIGH (non-restrictive):
    → Firmware interprets as "safety limit only"
    → Allows CV mode selection to proceed
    → Example: CV with 1224W power limit → CV mode

STEP 3: Determine SOURCE vs SINK direction
  - Compare battery voltage to voltage setpoint (REG 500)
  - If battery V < target V: SOURCE mode (charging)
  - If battery V > target V: SINK mode (discharging)

CRITICAL RULES FOR CV MODE:
  1. Only REG 500 (voltage) should be non-zero setpoint
  2. REG 9004 (power limit) must be HIGH (>1000W) to avoid CP mode
  3. REG 9002 (current limit) provides current constraint without mode change
  4. Sink registers (498/499): ZERO for SOURCE, DECOY for SINK
